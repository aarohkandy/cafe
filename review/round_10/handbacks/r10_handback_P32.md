# Round 10, look-ahead hand-back P-32: the ledger hashed a shared cache manifest that a later run rewrites

Branch `r10-la` (worktree `../cafe-r10la`, from `6c1fde7`). Tests ran on cafe-orca (`PM_HOST=cafe-orca PM_RUNTIME=proot`, 2 CPUs per job, `PMX=pm_r10la*`). Docs (DECISIONS, CHANGELOG, RUNBOOK) are not edited here, except the one quoted output line in `docs/CREDIBILITY.md` (hangar wording, below); the text for them follows.

## 1. P-32

Root cause, in the one shared place: `Ledger.input` hashes whatever file it is given, and ingest gave it the shared cache manifests (`orca/manifest.json`, and `tao/s2/manifest.json` in `_tao`), and listed the orca one as an output too. Both are rewritten in place by a later run (`orca.assemble`; `tao.fetch_tao`, called when `_tao_cached` / `_orca_covers` say the cache does not cover the new window, box or 3-D hour). Reproduced on the code of `6c1fde7` (orca, a scratch test, removed): ingest, then the orca manifest rewritten with one more part gave "input .../orca/manifest.json changed since the stage ran" and the same line for the output; `tao.fetch_tao` for a window a day wider on each side gave "input .../tao/s2/manifest.json changed since the stage ran".

Fix:
- `Ledger.snapshot(src, dest, **meta)` (`cafe/pm/ledger.py`): copies the bytes the stage read into the run (atomic: `.part`, then `os.replace`) and records the copy as the input, with `shared` = the cache manifest it came from. Everything that already works on inputs (hash at record time, `done`, the audit's hash line, `resolve` for a copied run) works on the copy unchanged.
- `pipeline.s_ingest` snapshots the orca manifest to `ingest/orca_manifest.json` (input, and the output that was `L.output(man)`); `pipeline._tao` snapshots the TAO manifest to `ingest/tao_manifest.json` (input).
- `audit._shared_problems` (`cafe/pm/audit.py`), called from `ledger_problems` for an input that has `shared`: the shared manifest is not read; each file the copy names must lie in the cache directory (the folder of `shared`) with the hash the copy has. Orca `parts` (`hours/<name>`): present and different is a problem naming the file, absent is not (as `_orca_problems` always did: the assembled stores that were read are inputs of their own). TAO `files` (`<mooring>/<name>`): different is a problem, absent is a problem ("is missing (the stage read it, tao_manifest.json lists it); run `fetch` again"). Where the cache directory does not exist (a run copied to another machine) nothing is compared.
- A ledger without `shared` (every run made before this) keeps the old check, including `_orca_problems` for an input named `manifest.json`.

Deviation from the decision, on purpose: the decision says every file entry of the snapshot "must still be in the shared manifest with the same hash". The check is on the files in the cache directory instead, and the shared manifest is not read. Reason: a window outside the cached one makes `fetch_tao` write a manifest for that window only (`man["files"]` is built from the new window's candidates), so the entries of an earlier run's files leave the manifest while the files stay on disk untouched. Asking the manifest would fail that run for a change that did not touch anything it read; asking the files fails exactly when a file it read changed or vanished. A truncated shared manifest is no longer a problem of an earlier run for the same reason (the audit of the cache is `tao.verify` / `_tao_cached`'s).

How the copied-run wording (M-19, RUNBOOK) treats it: a run copied to another machine with no cache directory used to report every shared input as "is missing (the stage read it)", the cache manifests included. Now the manifest lines are gone (the copy is in the run, and is hashed), and the lines for what is still outside the run and has to be there (the orca stores, the ocean store, GEBCO, the derived layer) are as they were. A copy that has the cache directory but not the file is told so.

Callers checked: `Ledger.input` unchanged (snapshot calls it). `ledger.done` reads the input of the copy, so an ingest whose shared manifest grew after it ran is now "up to date" on resume, where it re-ran before; nothing in `done` read the cache files and nothing now does (the orca stores' `tree_sha256` and the derived layer's still make `done` rerun when those were rewritten). `audit._orca_problems` (kept for old ledgers), `_dir_problems`, `ledger.rerecord` (works on outputs; the copy is an ordinary output), `resolve`/`run_roots` (the copy is under `ingest/`, in `RUN_DIRS`; a copied run resolves it: tested). Readers of the orca/TAO manifests in the pipeline (`_orca_covers`, `_tao_cached`, `tao.load_tao`, `key = digest(orca=sha256(man) ...)`) read the shared manifest as before; nothing reads the ingest outputs downstream (grep). Tests that asserted the old shape were changed to the new subject, not weakened: `test_pipeline.py` (output name `orca_manifest.json`, TAO input found by `shared`), `test_ingest_fetch.py` (three assertions: the ref is the copy, `shared` is the cache manifest).

Sweep of every other input the ledger hashes (by reading every `L.input` site in `pipeline.py` and `stage3/pipeline_windows.py`):
- fixed: the orca manifest as an *output* (same defect, same fix); TAO manifest; orca manifest.
- not fixed, P-34, reproduced for the derived layer: shared stores rewritten whole by a later run: the four orca stores (`orca.assemble`), the ocean store (`hycom.fetch_gofs`), `derived.zarr` (rebuilt when its key changes; the key holds `code_digest`, so after any code change). A scratch run (ingest in r1, ingest in r2 with another `code_digest`, audit r1) gave "r1: stage ingest: input .../derived.zarr changed since the stage ran (tree ...)", clean before r2. The manifest copy does not help: the bytes the run read are gone, and a copy of the stores is gigabytes. This is the owner's call; options are in P-34. It matters for the goal of P-32: after this fix a grown TAO cache no longer fails earlier runs, but an orca cache that is *rebuilt* (assemble) still fails them through the stores, and every code change still fails them through the derived layer.
- left hashed in place on purpose: the stored sphere grid studies (`nest_sphere_*_d*.json`, `s_refit`; rewritten by `receipts`, and a changed study is meant to rerun the refit), `platforms/*.yaml` and `config/assumptions.yaml` (a person edits them), GEBCO (named by box, fetched only when unreadable), the emulator training table (already a snapshot), run-own files.

## 4. P-32 follow-up (adversary): the resume and the missing cache directory (P-39)

Two gaps in section 1, proved by an adversary; both fixed in the shared place.

- `ledger.done` hashed only the copy of the manifest, so a TAO file replaced after the run (the shared manifest rewritten with its new hash) still resumed the stale ingest (`tao_compare.json`, fitted sigmas). Fix: the file comparison is one helper, `ledger.shared_changes(man, root)` (an orca part counts when present and different, a TAO file when different or gone), used by `done` and by `audit._shared_problems`. `done` returns None when it reports anything, and also when the cache directory is gone (the answer before P-32, when the shared manifest was the input; a ledger whose other hashed inputs live in that directory returned None for the same reason).
- `audit._shared_problems` returned [] when the cache directory was missing. Now `Ledger.snapshot` stores `shared` absolute (`os.path.abspath`; a relative one was read against the cwd of whoever audited), and a missing directory is a problem line when the run is where it was made (`audit._same_place`: `machine.host` is this host and the run directory is a place `run_roots` found in the ledger's outputs), and a note on stderr otherwise (a copied run: other machine, or moved). An old ledger with a relative `shared` is judged by the same rule, so it is told when it is in its own place and the relative path does not resolve.
- Callers checked: `done` (pipeline `s_ingest`, `_tao` and every stage), `audit._stage_problems` (the only caller of `_shared_problems`), `Ledger.snapshot` (two call sites in `pipeline.py`; `shared` is read nowhere else: grep). The test that asserted [] for a missing directory is the adversary's case and is replaced by the two-sided one below; the copied-run test in `test_ingest_fetch.py` is unchanged and passes (the copy is in another place).
- Limit: `_same_place` needs an output in the run's layout (`RUN_DIRS`) to find the run; every stage has one. A ledger with none cannot say where its run was and is treated as a copy (the note, no problem).
- Tests, each shown failing on the code of `b33a89a` in a detached worktree (removed): `test_ledger.py::test_p32_a_resume_notices_that_a_file_the_copy_names_changed_or_the_cache_is_gone`, `test_audit.py::test_p32_without_the_cache_directory_a_run_in_its_own_place_is_told_and_a_copied_one_is_checked_by_its_copy`, `test_audit.py::test_p32_a_cache_path_recorded_relative_is_judged_where_it_was_not_where_the_audit_runs`.
