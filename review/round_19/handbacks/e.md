## M-11: a half-deleted aside, and the advice for a missing store

- `hycom.py`:
  - `_leftovers(out, suffix)` is the old `asides` body (a directory, not a link, `<stem>[12 hex]<suffix>`); `asides` is `.old.tmp`, new `dead` is `.dead.tmp`.
  - `_delete_aside(q)`: rename `q` to `<stem><12 hex>.dead.tmp` (one rename), then `rmtree` it. If the rename fails the aside stays whole under its own name (the next locked write sweeps it) and the write does not fail. `write_store` uses it for its own old store and for the locked sweep of earlier asides. A kill before the rename leaves the aside whole (offered, true); after it, the half-deleted tree has a name nothing offers.
  - `write_store` also deletes every `.dead.tmp` of the store's name whether or not the lock is held. Reason (my decision, beyond merged.md's "the next locked write sweeps"): a dead tree is by construction out of use (renamed out of the store's name and never read), so no other writer can be hurt, and a lab store is never locked, so otherwise its dead tree would stay for ever on a 97 %-full disk. The `.old.tmp` sweep stays lock-only (that one may be another writer's live aside between its renames).
  - `leftover_note(path, lab)` (new, public): the text `unreadable` built for a missing store, moved out so `pipeline` can say it too. Returns "" when the store exists (`mv` onto an existing store moves the aside INSIDE it) or no `.old.tmp` is there. The text now also says what stays (P-R18M2, below), and for a lab store says that nothing deletes its leftovers (a lab store is not locked) and names `ls -a` of its directory. `unreadable` calls it; its wording keeps every substring the old tests pin (`mv <aside> <store>`, `without a download`, `GB)`, `lab's source`).
- `pipeline.py`: `_need` gets `leftover: Callable[[], str] | None = None`; a failing check appends `leftover()` to its note (offline, failed fetch, and a fetch that returned without making the input). Only the ocean-store call passes it (`hycom.leftover_note(store, lab)`). `s_ingest` is what both `run` and `fetch` run first, so both now print it where they meet the missing store (the lab store always, since it is never fetched; a GOFS store when offline or when the fetch fails; an online GOFS run just reassembles from `.parts` and the locked write sweeps the leftover itself).

The build directory comes from `atomic.tmp_name` (batch D's file) and carries nothing of the store's name; a build in progress by another ingest is not told apart, and the build happens outside the lock, so a sweep by name would be the P-R16C2 class (deleting a running writer's build).
