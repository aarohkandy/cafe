## M-1: a Stage-1 row is judged by the verdict of the unchanged mission on its own members

`whatif.flip_search` now finds the baseline BEFORE it judges a Stage-1 row: free from `base_failed` (as in round 17), else measured first and charged one batch of the vehicle's share (a UAS in a 3-D wind is always measured, as before). The row's target (`target_same`), the early stop and `hit` use the baseline's VERDICT on those members through `_better_than` (NO-GO: GO or MARGINAL; MARGINAL: GO; GO: nothing, then no Stage-1 row is run and the reason on each left candidate says "Stage 1 not run: the unchanged mission is already GO on the candidates' own members"). Emulated rows keep the whole run's target (the emulator predicts the full ensemble); `target` stays the whole run's. When the share does not cover even the baseline, no row is run either and `target_same` is None (the report says the baseline was not measured). `flip.json` gains `target_same` per vehicle (None when no same-members baseline); `report.json` `fix.target_same` carries it (None for an older `flip.json`, which renders as before). `report._fix_html`: the badge left of the pair is the same-members verdict, with "(whole run: NO-GO)" beside it when it differs; the heading "What would fix it (GO)" names the target the best row was judged against; the muted same-members paragraph says what a Stage-1 row must reach and the whole run's target when they differ, or that the unchanged mission is already GO on those members. Sibling sites read, right as they were: `whatif.answer` (re-measures the baseline on the answer's n, with its verdict) and `report._fix`'s `same_as_baseline`.

What this costs, and the pins that moved because of it (no assertion weakened; each is the same intent with the number the new order gives): a share is spent baseline first, so a share of `2.5 * cost` split over two vehicles now buys each only the baseline (tests use `4.5 * cost` for the same "each gets one candidate", spent `4 * cost`); the UAS test "the candidates come first, a share that covers only them leaves the baseline unmeasured" became "a share of `0.9 * cost` leaves it unmeasured, `3.5 * cost` runs the baseline and two rows"; "a baseline that leaves the data comes after the candidates" became "the first call". Round 17's `..._a_share_that_covers_only_the_candidates_leaves_the_baseline_unmeasured...` is now "...covers_no_batch...". The pipeline passes the base run's flags, so the real runs pay nothing more (the demo below spends the same 69.29 s).

Decision for the lead (it is the default of OD-1 and nothing else was possible without a verdict): with no flags and a share of exactly the K candidates the old code ran K candidates against the whole run's verdict; the new code runs K-1 against the right verdict. Only callers without flags see it (the tests; the pipeline always passes them).

## M-5: `whatif` takes its members from the run's own plan.json

`--budget` defaults to None. When `<run>/plan.json` exists: its `budget` is the budget; a given and different `--budget` is a `ConfigError` naming both and the batch ("--budget ci: the run <dir> was made with --budget quick, and whatif draws its members from that plan (batches of 32); leave --budget out, or use --run of a run made with --budget ci"); `Context` is built with the run's budget and `ctx.plan` gets the run's `batch`, `n_min`, `n_max` (this machine's plan supplies the rest; the planner's batch depends on this machine's throughput, so the run's sizes are copied, not recomputed). A damaged plan.json is the usual "damaged or incomplete (KeyError: ...)" message. With no plan.json the old behaviour stands (`--budget`, default quick). Not changed: `--gpus` (the run's gpus are not read; the sizes that matter are copied). The module usage line and the `--budget` help text say so. Tests: `test_m5_a_budget_that_is_not_the_runs_is_refused_naming_both`, `..._the_ensemble_of_the_fallback_is_the_runs_own_and_not_this_machines_plan_for_the_budget` (batch 24, n_max 72 in plan.json), `..._a_run_made_with_another_budget_is_answered_with_that_budgets_plan`, `..._a_directory_with_no_plan_keeps_the_budget_...`, `..._a_damaged_plan_json_is_the_damaged_file_message_...`, `..._the_budget_flag_has_no_default_and_the_help_says_whose_it_is`.
