## M-14: `python -m cafe._seed` did not look at what it seeds

- Changed: `cafe/_seed.py`. Two phases: every file that exists is read and checked first (`_checked(what, k, r)`); if any is unusable, each is printed as `NOT seeded <file> - <reason>` (stdout, like the existing NOT seeded lines), one line to stderr says `nothing was seeded: N of the M files cannot be used ...`, exit 1, and the cache is not touched (not even for the good files). Only then does the loop of `cfd.cached` run, with the `seeded` / `already there` / `NOT seeded <key> - <warning>` output unchanged. A file that cannot be read (`OSError`), is not UTF-8 or not JSON (`ValueError`) is the same message with the reason. "No old runs found" message and exit 1 unchanged.
- The shape asked of a result (what `vehicle.py` and `hangar.py` read): `external`: a dict; `fluid` and `speed` equal to the key's (the case's own: air at 10.0 for the UAV sample, water at 1.5 otherwise); `rho`, `nu`, `L` finite numbers (not bool); `dirs` a non-empty object whose keys are among `cfd.DIRS` and each value has `force`, `moment`, `viscous` as lists of three finite numbers. `surface`: a dict; `speeds` a non-empty object whose keys are numbers and each value a dict with a finite `resistance`; the rounded speeds equal the case's speeds (the key's list). The conversion of the string keys of `speeds` to floats, which `_seed` did before, is done in `_checked`.
- Decision taken (beyond the finding's text): I also refuse a file whose `fluid`/`speed` (external) or speeds (surface) are not those of the case it would be cached under, because that is a result of another case cached under the real key, the same harm as a wrong shape. A file made by `python -m cafe.cfd external|surface` for the shipped samples has exactly these values, so it is still accepted (the test builds such files, with the extra keys a real run adds: `level`, `mesh`, `seconds`, `gci`, a stamp). I could not read the real `/work/runs/*` files of the app image, so "every file legitimately seeded today still seeds" is shown on files built to the shape `characterize_external` and `characterize_free_surface` return (read in `cfd.py`), not on the real ones.
- Pins moved: `tests/test_round17_e.py:337` and `tests/test_round18_d.py:176` seeded a stand-in `made = dict(L=1.0, dirs={"+x": dict(force=[-1.0, 0.0, 0.0])})`, which is not a result (no `fluid`, `speed`, `rho`, `nu`, `moment`, `viscous`) and is now refused. Both now use a valid minimal external result (`fluid="air", rho, nu, speed=10.0, L, dirs` with the three vectors). Their assertions are unchanged. `tests/test_round18_d.py` is not on batch D's file list; it is owned by no other batch and the pin cannot stay as it was.
- Test: `tests/test_round19_d.py`: 20 bad external files (`[1,2]`, a number, `null`, `{not json`, empty, `{}`, no `dirs`, no `rho`, `L` a string, `nu` a bool, `NaN`, no `force`, a force of two numbers, a string in a force, a direction that is no axis, empty `dirs`, a direction value that is a list, the fluid or the speed of another case, invalid UTF-8) each exit 1 with `NOT seeded <file> -` and no cache directory; a directory in place of the file (OSError); a good quad plus a cut torpedo: nothing cached; both bad files named; 8 bad free-surface files; the three shipped cases with real-run extras seed (the wigley file's `speeds` keys written as strings by JSON) and a second run says `already there` three times; no file: the one-line message, exit 1.
