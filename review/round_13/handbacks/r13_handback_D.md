## M-28: perturbation entries are validated once, where they are read

**DECISIONS row.** `config/perturbations.yaml` entries are refused where they are read, by one function, `sampling.check_entry(k, e)`, which raises a `ValueError` naming the entry (`perturbation 'k': ...`). It is called by `load_perturbations` for every entry (after the existing field-presence check) and by `to_marginals` for every entry it builds, so a fitted prior that `stage1.priors_for` puts over a file entry (`pri.update(fitted)`, ingest/priors_fitted.json) is checked at the same place. The rules: the entry is a mapping; `dist` is one of `normal`, `lognormal`, `uniform`, `fixed` (a missing `dist` was a `KeyError`, and `truncnorm` is no longer accepted as an entry: it was refused by `to_marginals` with "not a sampled parameter" already, and only tests use it; `marginal()` still builds it for a direct call and says so in its docstring); normal and lognormal: `value` a finite number, not a bool, greater than 0 (a YAML `true` was read as an sd of 1), `mean` (normal) finite and `median` (lognormal) finite and > 0 when given; uniform: `lo` and `hi` finite numbers with `lo < hi` (a reversed pair loaded and `lhs` returned NaN for every member; `value` of a uniform is unused and is not checked, as before). A file that is empty, an empty mapping or not a mapping is a `ConfigError` naming the file ("expected a mapping of perturbation entries, found nothing / list"); `foo: 3` is "perturbation 'foo': an entry is a mapping ... not 3" (it was an AttributeError). `marginal()` itself does not check its numbers (a direct `marginal(dict(dist="truncnorm", sd=0, ...))` is still a ZeroDivisionError and `normal` with sd 0 gives NaN): it is fed only from `to_marginals` in the pipeline. `dist` is now required in `load_perturbations` (every shipped entry has one; `to_marginals` needed it for all but the field-presence tests).

## M-34: `subset_simulation`

**DECISIONS row.** `subset_simulation` uses one level probability, `q = nc / n` with `n` already rounded to `nc * length`, in both the c.o.v. term `(1 - q) / (q n) (1 + gamma)` and the probability product (the c.o.v. term used the nominal `p0` and the product `nc / n`; they differ unless `n p0` is a whole number that divides `n`: n = 1000, p0 = 0.3 gives 300 chains of 3 = 900 samples, q = 1/3, and the per-level term 0.002593 (nominal) against 0.002222 (realised), 16.7 % high). It raises `ValueError` when `n p0` rounds to no seed (`nc < 1`: n = 4, p0 = 0.1 was a ZeroDivisionError) and, beyond what the finding said, when the chain length `n // nc` is below 2 (n = 10, p0 = 0.6 was an IndexError on `order[nc]`, and a chain of 1 does no moves). No gate number moves: the function has no caller outside tests, and the two pinned c.o.v. runs (n = 200 with p0 = 0.1 and 0.2) have `nc / n == p0` exactly, so they pass unchanged.

**Amends.** Row 366 (the c.o.v. rows: add "the level probability in the c.o.v. term is the realised `nc / n`, as in the product") and row 73 (add: "refuses an n and p0 that leave no seed or a chain shorter than 2"). Neither contradicts.

**CHANGELOG line.** Round 13 M-34: `subset_simulation` uses the realised level probability `nc / n` in its c.o.v. as well as in the probability (it used `p0` in the c.o.v.: 16.7 % high per level at n = 1000, p0 = 0.3), and refuses an `n` and `p0` that leave no seed or a chain shorter than 2 with a ValueError (n = 4, p0 = 0.1 was a ZeroDivisionError). No caller; no gate number moves.

**Doc sentences.** PHYSICS 13.5: "n is rounded to a multiple of the chain count nc = round(n p0); the level probability used in both the estimate and the c.o.v. is nc / n, which equals p0 only when n p0 is a whole number dividing n. n p0 below 0.5 (no seed) or a chain length below 2 is refused."
