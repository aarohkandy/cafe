Why two kinds of rule (this is a deliberate departure from "exclude them all"): an excluded path is neither sent nor deleted. The tracked ones (`config/throughput.json`, `config/subgrid.json`, `tests/golden/`, `report/`) are also in the checkout, and a plain exclude would freeze the server's copy: an edited tracked file would never reach the server. `P` (protect) keeps the server-only copy from being deleted and still lets the checkout's copy go over, as it did before. Test: a server `config/throughput.json` ("server") and a checkout one ("local") ends "local"; every other output survives.

Sibling sweep for this list: the old unanchored `cache` and `site` excludes were kept exactly (they also match nested paths); everything new is anchored to the tree root so it cannot hide a source file. `tests/test_runners.py::server_outputs` builds the paths from the code constants (`audit.MUTATION_FILE`, `audit.LOG`, `audit.MUTATION_STATS`, `report.RECEIPTS_NAME`, `acceptance.GOLDEN`, `budget.THROUGHPUT`), so a renamed output makes the test fail instead of the list going stale.
