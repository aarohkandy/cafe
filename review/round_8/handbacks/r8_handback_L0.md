## Findings

### 1. audit crashes on a truncated orca or TAO manifest.json
- `cafe/pm/audit.py`: `_Unreadable`, `_read_json` (object or `_Unreadable` naming the file); `_store_attr`, `_orca_problems` and the manifest check read through it; the per-input body of `ledger_problems` catches it and appends `<run>: stage X: input F is not valid JSON (...); delete it and run \`fetch\` again`. The ledger.json read (M-23) uses the same helper with its message unchanged.
- Covers the sibling of finding 5 (a store's `zarr.json` / `.zattrs`) in the same place.
- Tests (tests/test_audit.py): `test_r8_l0_a_truncated_orca_or_tao_manifest_is_a_problem_naming_the_file_not_a_traceback` (a 5000-byte cut, `[1,2`, empty, `[1]`), `..._a_store_with_a_truncated_zarr_json_...`, `..._a_truncated_orca_part_manifest_...`.
- Mutants killed: `audit_input_handler` (handler removed: 2 fail), `audit_orca_bare` (bare json.loads in `_orca_problems`: 1 fails).
- DECISIONS: `| ? | Every JSON file the audit reads out of a ledger's inputs (an orca or TAO manifest.json, a store's zarr.json or .zattrs) goes through one reader; a damaged one is a problem line "input F is not valid JSON (...); delete it and run \`fetch\` again" and the audit goes on. | Review round 8, lead item L0. M-23 guarded ledger.json only; the manifests are ledger inputs and any truncated one ended the audit in a traceback instead of naming the file. |`
- CHANGELOG: `The audit names a truncated orca/TAO manifest.json or store zarr.json in a problem line instead of ending in a traceback (review round 8, L0).`

### 2. a truncated derived.digest.json crashes run and fetch
- `cafe/pm/pipeline.py` `_derived_current`: both JSON reads go through a local `read()` that returns None for an unreadable, empty or non-object file; None means "not current", so ingest rebuilds the layer. `cafe/pm/env/surface.py` `build` writes the digest to `derived.digest.tmp` and `os.replace`s it, as `Ledger` does.
- Tests: `tests/test_pipeline.py::test_r8_l0_a_truncated_derived_digest_or_zarr_json_is_a_layer_to_rebuild_not_a_traceback` (both files, three damages, the keyless call, and an ingest that rebuilds); `tests/test_surface.py::test_r8_l0_the_digest_record_is_written_whole_or_not_at_all` (a write that dies after 10 bytes leaves the old record whole).
- Mutants killed: `derived` (old function body), `digest_atomic` (in-place write).
- DECISIONS: `| ? | A derived-layer record (derived.digest.json, derived.zarr/zarr.json) that cannot be read is a layer that is not current: ingest rebuilds it (about 150 s). \`surface.build\` writes the digest through a temporary file and os.replace. | Review round 8, lead item L0. A kill or full disk right after the build left a cut-short file, and every run and fetch then ended in a JSONDecodeError. |`
- CHANGELOG: `A truncated derived.digest.json or zarr.json is rebuilt by the ingest instead of ending it in a traceback; the digest is written whole or not at all (review round 8, L0).`

### 3. the M-11 hint "use 1e-6" sends the user to a spelling YAML read as text
- Root: `config._Loader` gets an implicit float resolver for the digits-e-digits form (`1e-6`, `5e0`, `1e+7`, `-2E3`, `1_0e1`); `config.read_yaml` (an alias of `_yaml`) is the one reader (finding 8). The hint is now true as written.
- Changed existing test: `tests/test_config.py::test_r8_m39_...` case `5e0` (it asserted that `5e0` is refused as text) is now the quoted `"5"`, which still gets the message "written in a form YAML reads as text ('5'); write 5"; the case name and the `_say` docstring say so. `5e0` itself loads (new test). No assertion was weakened: the premise (an exponent without a dot is text) is what this finding removes.
- Test: `tests/test_config.py::test_r8_l0_an_exponent_without_a_dot_is_a_number_in_every_file_and_the_hint_names_a_spelling_that_loads` (text, quad_uas `r_int_ohm: 1e-6`, perturbations `-3.5e-1`/`-3e-1`, mission `radius_km: 5e0`; quoted and malformed forms stay text).
- Mutant killed: `float_resolver`.
- DECISIONS (amends the round-8 M-39 row): `| ? | A number written as digits, e, an optional sign and digits (1e-6, 5e0, 1e+7) is a float in every YAML file the pipeline reads, as it is in YAML 1.2; PyYAML (YAML 1.1) reads it as text. The M-11 hint "use 1e-6" is therefore true; the M-39 message "written in a form YAML reads as text" stays for a quoted number. | Review round 8, lead item L0. The hint recommended the spelling that platform and perturbation files then refused (or, in perturbations.yaml, carried as a str into the sampler). |`
- CHANGELOG: `YAML files take 1e-6, 5e0 and 1e+7 as numbers (they were text outside the mission schema's message); the r_int_ohm hint is true as written (review round 8, L0).`

- Bounds are gross-error limits, checked against the real demo cache on cafe-burst (per-field min/max printed): e.g. WRF T2 297 to 303 K inside [230, 330]; GLW 372 to 458 inside [0, 700]; ocean u -1.10 to 1.18 inside [-5, 5], water_temp 0.4 to 30.2 degC inside [-3, 40], salinity 33.3 to 36.6 inside [0, 45].
- Honest limit: as for the four existing fields, a value inside a wide gross-error bound (winds x 3) passes; the u* fraction and the Data pedigree rule catch those.
- Tests (tests/test_pipeline.py): `..._the_forcing_check_covers_every_wrf_umwm_and_ocean_field_...` (every key is a documented assumption, every field exists in the env), `..._one_wrf_value_of_1e6_in_any_field_...` (14), `..._one_umwm_value_of_1e6_...` (5), `..._an_absurd_current_temperature_or_salinity_...` (4, plus an infinity), `..._nan_in_the_ocean_store_is_land_...`. The existing M-1 tests are unchanged and pass.
- Mutants killed: `ranges_old` (the two new tables and the ocean loop removed: 23 fail), `ranges_ocean_only` (4 fail).
- DECISIONS: `| ? | The ingest check forcing_in_physical_range bounds every WRF 2-D field the model reads (wind speed, SST, T2, TSK, Q2, PSFC, SWDOWN, GLW, PBLH, HFX, LH, QFX, RAINC, RAINNC, the derived rain rate, UST), the UMWM fields at sea nodes (swh, ust, dwp, mss, wspd) and the ocean store's currents, temperature and salinity, with gross-error bounds in config/assumptions.yaml \`ingest.*\` (17 new entries). M-1 bounded four fields; a unit slip in the currents that drive the glider and USV drift, in SWDOWN or in the temperature and salinity passed with Data pedigree at 2. |`
- CHANGELOG: `The ingest forcing check bounds all 14 WRF fields, 5 UMWM fields and the ocean store's currents, temperature and salinity, not wind, swh, SST and ust only; 17 new ingest.* bounds in assumptions.yaml (review round 8, L0).`
