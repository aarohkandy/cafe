## M-12. acceptance deletes only a directory it made itself

What changed: `acceptance.claim_out(out, names)` and the constant `MARKER = ".cafe_acceptance"`. `run_one` calls it right after `refuse_wiped_mission` and before the first `shutil.rmtree` (so both rmtree sites, `out/<name>` and `out/<name>_fetch`, sit behind it); `run` calls it once for every name in `RUN_NAMES`, so a user's `overnight` or `4h` is protected before the first run starts, not after hours.

Rule: if `out/.cafe_acceptance` exists, acceptance made or claimed `out`: replace as before. If it does not exist, `out` is refused (`config.ConfigError`, exit 2, nothing touched, no marker written) when it holds `<name>`, `<name>_fetch`, `<name>.log` or `<name>_fetch.log` for any name asked, or `plan.json` or `checkpoints` (it is itself a run). Otherwise (missing, empty, or holding only other files) acceptance writes the marker, then runs. The marker is written before the first rmtree, so a run killed half-way is rerunnable. The guard also covers the two logs that `_execute` overwrote.
