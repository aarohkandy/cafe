## Root causes

R1. Stored nulls and zeros are read back without a checked load (M-1, M-5, M-7; M-6 on the write side).
- Place: the pipeline writes NaN as null (`ledger.clean`) and zero counts, and readers coerce with bare `float()` or divide by `n`. One fix each at the readers: `credibility._data_pedigree` (a `_num` helper), and one summary validator shared by `credibility.Facts.ensembles` and the report loops (n >= 1, 0 <= k_fail <= n). `config.damaged_run_files` gets the corrected advice text so a real bug is no longer sold as damage.
- Siblings: tao_compare.json is read only in credibility.py:487-494; report.py:430-431 (sensitivity cases); `intervals.interval` ValueError; windows.json limits and other `_dump` outputs read with `float()` (grep across report.py and audit.py not done).
- M-6 (calm window): `_ustar_agreement` and `_spectrum_errors` both reduce a calm to "no sea nodes"; fix in the shared `_sea_sample` consumers.

R2. The ledger does not record what a stage actually read, or cannot tell a rewrite from damage (M-2, M-8, M-9, M-10).
