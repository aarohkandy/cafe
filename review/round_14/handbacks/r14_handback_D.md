## M-33. `orca_gate.sh` turns any tag into a directory that `rsync --delete` empties; `pmx.sh` has no in-use guard

A marker that names another checkout is refused, exit 1, nothing synced (`STOP: work/cafe/pm_x on <host> belongs to <owner>, and a sync from here (<me>) would --delete its files under a running job. The sync keeps the marker with `--exclude=/.pmx.owner` inline in `pmx.sh` (not `bin/sync_filters`), and the marker is written after the sync (`mkdir -p` and `printf`). `bin/orca_gate.sh` no longer defaults `PMX` to `pm_<tag>`: with `PMX` unset or empty it exits 2 with nothing sent (`PMX=pm_<you> is required`), after the K and tag checks.

Code (`bin/pmx.sh`, the one place every caller passes through): a TM= job now writes its session name to `~/$R/.pmx.job.$D` (beside the directory, not in it, so the `--delete` never sees it and no exclude rule was added; `bin/sync_filters` untouched) before `tmux new-session`.
