### M-18 (config.write_text keeps the mode)

Code. `config.write_text` copies the permission bits of the file it replaces onto the temporary before `os.replace` (`shutil.copymode(p, tmp)`, an `OSError` ignored: a new file has none, and then it gets the default). Every caller of `write_text` and `write_json` inherits it. The docstring says the hard-link limit: a replace gives the name a new inode and the other name keeps the old content.

DECISIONS: amend 706 (it says a chmod 400 file becomes 0644): "A chmod 400 file in a writable directory is replaced by a new file with the same mode (0400; round 14, M-18); a hard link to it is not kept, because `os.replace` gives the name a new inode and the other name keeps the old bytes, so `config.write_text` is for a file with one name." Amend 739 (the one-writer row) with "an existing file keeps its permission bits; a new file gets the default ones". No new row needed.

CHANGELOG: "`config.write_text` keeps the mode of the file it replaces (a 0600 file stayed 0644 after the first rewrite); a hard link to it still does not survive, and the docstring says so (round 14, M-18)."

Doc sentences. None beyond the rows. The shared golden's mode is now whatever it had.

Could break, checked. (1) A 0400 target: the temporary is written first and then given the mode, so the write works; the directory must be writable (it always had to be). (2) A symlink: `copymode` is applied to the realpath, which is the file replaced. (3) An absent target: `copymode` raises FileNotFoundError, which is an OSError and ignored. (4) Owner and group are not copied (a root-owned file replaced by a user keeps the user): not done, the finding made it optional; the files written are the person's own. Tests: `tests/test_config.py::test_r14_m18_*` (0600 stays 0600, 0400 stays 0400, new file default, symlink, hard link limit), and the whole of `test_config.py`, `test_acceptance.py`, `test_audit.py`, `test_receipts.py` pass.
