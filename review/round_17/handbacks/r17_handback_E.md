## M-4 The CFD cache key and every number and text in the code

What I chose: hash the numbers and texts written in the code (not named constants). The finding's default (named constants listed in `SETTINGS`) fixes the ten sites named and misses the next edit by construction; a test that forces them in cannot see a literal added later. The mechanism here has no list to forget:

- `cfd._literals(src)` parses the module text and, for every top-level function and class not named in `cfd.NOT_KEYED`, takes every constant (int, float, str, bool, None, the constant parts and format specs of f-strings, the defaults of the arguments) in source order, except docstrings and bare strings, anything inside a `log(...)` or `print(...)` call, and anything inside a `raise`. It returns the sha-1 of that list. `cfd._code_literals()` is that of `cfd.py` itself, cached for the process. `cfd.recipe()` hashes `SETTINGS` plus this digest (`"code"` key). So the mesh sizes, the 1500 iterations, the 0.2 averaging window, the 0.3 refine threshold, `includedAngle 150`, the `locationInMesh` fractions, `surf_level`, the inline fvSchemes, fvSolution, controlDict and transportProperties texts, and the argument defaults are all in the key. This also removes the limit DECISIONS 910 and the M-23 limit of the reviewer prompt name (the inline OpenFOAM texts): they are in now.
- A new function is keyed by default; only `NOT_KEYED` (`recipe`, `cached`, `_code_literals`, `_literals`, `_text_and_numbers`, `_plain`, `main`) is out. A test holds that list to the file and a second test adds a function, a class and a literal to the text and sees the digest move.
- `INCIDENCE_ALPHAS = (5.0, 10.0)` is a new module constant in `SETTINGS`; `characterize_incidence`'s default `alphas` is it and `hangar.py:314` writes `cfd.INCIDENCE_ALPHAS` in its key instead of its own `(5.0, 10.0)` (the status text "hull lift at 5 and 10 deg" is built from it too). The hand-written label `"3-grid"` stays: it is a deliberate cache bust, not a copy of a default.
- Python-version dependence: none worth naming. `ast.Constant` values and f-string parts are the same on 3.9 to 3.12 (the image runs 3.12); this is not `co_consts`. A log or error-message edit changes nothing (the point of excluding them).

What remains outside the key, exactly: (a) the logic of the code (an operator, `min` for `max`, a name, a call, control flow: only its numbers and texts are hashed); (b) the other modules this file calls (`cafe.pm.vv.gci_two_grid` through `gci`, `trimesh`, `numpy`, `scipy`, `cafe.atomic`) and their versions; (c) the module constants named in `NOT_SETTINGS` (`NPROC`, by decision: cores change the time, not the answer); (d) docstrings, comments, log and raise text, by decision; (e) the call parameters the caller does not put in its `key` (`hangar.py` still rounds `draft` to 4 and the speeds to 3 places in the key and passes the unrounded ones to the compute, as before). A refactor that moves a literal from one function to another changes the key (the function name is in the digest): that recomputes once, the safe side.

Every cache file made before this change has another name and is never read again (the recipe has a new `code` entry, so even an unedited recipe renames them): the next CFD of every case runs once more, as when `SETTINGS` was introduced (DECISIONS 910).

## M-10 `cfd.cached` and a cache that cannot be written or read

`cached`: after `compute()`, `CACHE.mkdir` and `atomic.write_json` sit in `try/except (OSError, TypeError, ValueError)`; the result is returned and `log` gets "warning: the CFD result was not cached, so the next run computes it again (<Type>: <message>)" (OD-9). The write's `default` is `cfd._plain` (a numpy array or scalar as the list or number it holds; anything else `float(o)`, which is a TypeError the same guard catches), where `default=float` raised on an array of two numbers. The hit path reads inside `try/except (OSError, ValueError, KeyError, TypeError)`: a file that is empty, cut, `{"recipe": "x"}`, `[]`, `null`, a string, not UTF-8 or a directory is logged ("CFD: the cache file <name> cannot be read (<Type>: ...); computing again"), removed (`unlink(missing_ok=True)`; an OSError there is swallowed, a read-only cache then fails the write and says so) and the case computed again. "reusing an identical earlier run" is now logged after a successful read, not before. The atomic writer stays (a cut write leaves no file). The Hangar's callers already catch `Exception`; they now seldom see one from the cache. A hit returns what the JSON holds (arrays as lists, float keys of `speeds` as strings, as before; `vehicle.py:339` sorts by `float(kv[0])`, so both shapes are read); a miss returns the compute's own object.

DECISIONS row: `cfd.cached` never loses a finished result to its cache (OD-9): a write that fails with OSError, TypeError or ValueError (read-only or full cache, an object JSON cannot hold) is logged as a warning that names the error and the result is returned, and the next run computes again; the JSON `default` turns numpy arrays and scalars into lists and numbers. A cache file that cannot be read back (empty, cut, wrong shape, not UTF-8, a directory) is logged, removed and recomputed, not an error on every later call. Amends 910 and the round 15 cut-write test (`tests/test_config.py::test_r15_a_cut_write_of_the_cfd_cache_...` now asserts the return and the warning, not the OSError). Why: round 17, M-10 (D-2): on `pm.sh` and `pmx.sh` the default `CACHE` is under the read-only `/work`.

CHANGELOG line: `cfd.cached` returns a finished result when the cache cannot be written (warning in the log) and removes and recomputes a cache file it cannot read (round 17, M-10).

Batch G: the RUNBOOK's CFD-cache sentences should say "a cache that cannot be written costs the next run a recompute, not this run its result" and, for the lab: the runners mount `/work` read-only, so set `CAFE_WORK` to a writable directory to keep the cache.

Tests: `test_r17_m10_an_unwritable_cache_returns_the_result_with_a_warning`, `..._a_result_with_an_array_is_cached_as_lists_and_returned_as_it_was`, `..._a_result_json_cannot_hold_is_returned_with_a_warning_and_leaves_no_file`, `..._a_cache_file_that_cannot_be_read_back_is_removed_and_the_case_computed_again` (7 file shapes), `..._a_cache_entry_that_is_a_directory_is_computed_and_warned_about_not_raised`; `tests/test_config.py` hunk above.
